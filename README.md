# Spring book study guide

Open **[index.html](index.html)** in a browser for a plain-language companion to the two books in this repository:

1. *Spring Start Here* — 15 chapters and appendices A–G.
2. *Spring Security in Action*, second edition — 18 chapters and appendices A–B.

The guide includes key ideas, short illustrative code examples, 17 figures from the supplied PDFs, a chapter index, search, and a glossary. The examples are adapted and abbreviated for learning; they are not complete runnable projects. Check the documentation for the Spring version you use, particularly for security configuration.

**[Chapters 1–15 companion](chapter-01.html)** — the first fifteen chapters explained in plain language:

1. *Spring in the real world* — why frameworks exist, the Spring ecosystem, where Spring is used, and when to avoid it.
2. *The Spring context: Defining beans* — Maven basics and the three ways to add beans (`@Bean`, stereotype annotations, `registerBean()`), with the trade-offs of each.
3. *The Spring context: Wiring beans* — linking beans by direct call, method parameters and `@Autowired` (field, constructor, setter), circular dependencies, and choosing between beans with `@Primary` and `@Qualifier`.
4. *The Spring context: Using abstractions* — interfaces as contracts, a realistic comment-publishing design built first in plain Java and then with Spring, injection by interface, `@Primary` versus `@Qualifier` across implementations, and `@Service`/`@Repository`.
5. *The Spring context: Bean scopes and life cycle* — the singleton scope and what "one instance per bean name" really means, shared state and race conditions, eager versus `@Lazy` instantiation, the prototype scope with `@Scope`, the `CommentProcessor` example, and the trap of injecting a prototype into a singleton (with table 5.1's side-by-side comparison).
6. *Using aspects with Spring AOP* — aspect terminology (aspect, advice, pointcut, join point), weaving through proxy objects, the four steps to a working aspect, the AspectJ pointcut expression explained token by token, altering arguments and return values with `ProceedingJoinPoint`, intercepting annotated methods with `@ToLog`, the five advice annotations, and the aspect execution chain with `@Order`.
7. *Understanding Spring Boot and Spring MVC* — web app anatomy (frontend and backend), the two architectures (server-rendered views versus frontend–backend separation), why a servlet container exists and what a servlet is, Spring Initializr and the five files it generates, dependency starters, autoconfiguration and convention over configuration, then a first Spring MVC page with `@Controller`/`@RequestMapping` and the seven-step request flow through the dispatcher servlet.
8. *Implementing web apps with Spring Boot and Spring MVC* — dynamic views with Thymeleaf and the `Model`, the static-versus-templates folder distinction, request parameters with `@RequestParam` (and why they are mandatory by default), path variables with `@PathVariable` (with table 8.1's comparison), the five HTTP methods, and a product list built with `@GetMapping`/`@PostMapping` plus an HTML form.
9. *Using the Spring web scopes* — request, session and application scopes and how each one measures a bean's lifetime against HTTP requests, a request-scoped login judge, a session-scoped `LoggedUserManagementService` that remembers the user, the guarded main page and `redirect:` between pages, an application-scoped login counter, and the book's advice to avoid application scope in favour of a database.
10. *Implementing REST services* — REST as communication between two apps, the Spring MVC flow without a view resolver, `@ResponseBody` versus `@RestController`, testing endpoints with Postman and cURL, returning objects and collections as JSON, controlling the response with `ResponseEntity` (status and custom headers), exception handling inside the action versus a `@RestControllerAdvice` with `@ExceptionHandler`, and reading a JSON payload with `@RequestBody`.
11. *Consuming REST endpoints* — the payment-service scenario, OpenFeign (an interface plus `@FeignClient`, enabled with `@EnableFeignClients`), RestTemplate (`HttpHeaders`, `HttpEntity`, `exchange()`), why it is in maintenance mode yet still worth reading, and WebClient with the reactive model behind it (tasks, producers and subscribers, `Mono`), ending with the book's rule: OpenFeign for ordinary apps, WebClient only for reactive ones.
12. *Using data sources in Spring apps* — what a data store, DBMS, JDBC driver and data source each do, why connections are pooled (HikariCP), `JdbcTemplate` with `update()` and `query()` plus a `RowMapper`, the `@Repository` stereotype, `schema.sql` for examples versus Flyway/Liquibase in production, switching to MySQL through `spring.datasource` properties, and declaring your own `DataSource` bean when the defaults are not enough.
13. *Using transactions in Spring apps* — a use case with two mutable steps (withdraw, deposit) and the inconsistent data a failure between them leaves behind; transactions as atomic sets of changes, with **commit** (everything persisted) and **rollback** (data restored); the Spring AOP aspect that intercepts `@Transactional` methods and its try/commit/catch/rollback logic; why the method must *throw* a runtime exception for the rollback to happen, and why checked exceptions do not roll back by default; then the full `sq-ch13-ex1` wallet app — `schema.sql` and `data.sql`, `Account`, `AccountRepository` with `queryForObject`/`update`, `AccountRowMapper`, `TransferService.transferMoney()` under `@Transactional`, and the REST layer with `TransferRequest` — plus the cURL runs that prove the balances move, and `sq-ch13-ex2`, one added `throw`, which proves the rollback leaves the data untouched.
14. *Implementing data persistence with Spring Data* — why a dozen persistence technologies with a dozen APIs is a problem, and how Spring Data puts one set of abstractions above them; the module-per-technology rule (there is no single "Spring Data" dependency); the contract hierarchy `Repository` (marker) → `CrudRepository` (CRUD) → `PagingAndSortingRepository` (paging and sorting), plus technology-specific contracts such as `JpaRepository` and `MongoRepository`, and the interface-segregation reasoning behind the split; then the wallet app `sq-ch14-ex1` rebuilt with Spring Data JDBC — `@Id` on the model, an `AccountRepository` that is just an interface extending `CrudRepository<Account, Long>`, derived query names (`findAccountsByName`) and why the book discourages them, `@Query` and `@Modifying` for hand-written SQL, and the service/controller/cURL runs that show the transfer and the optional `name` filter.
15. *Testing your Spring app* — why a feature is only *probably* working until it is tested, and why regression tests plus a CI tool (Jenkins, TeamCity) catch breakage that manual clicking misses; one test class per method and one test method per scenario, kept in the Maven `test` folder; the three parts of every test (assumptions, call, validations — a.k.a. arrange/act/assert, given/when/then); **unit tests** with Mockito — `mock()`, `given().willReturn()`, `verify()`, the `@Mock`/`@InjectMocks`/`@ExtendWith(MockitoExtension.class)` flavour, `assertThrows()` and `verify(..., never())` for exception flows, and asserting returned values in the chapter 9 login controller; **Spring integration tests** with `@SpringBootTest`, `@MockBean` and `@Autowired`, when to mock and when not to, using H2 instead of the real database, and why integration tests should not be used for every scenario.

It embeds all 179 original figures from the fifteen chapters, plus 248 Java/XML examples. The side contents can collapse each chapter, and the chapter switcher at the top jumps between them. Use the chapter switcher at the top or the side contents to move between them.

## Reading locally

All 17 figures are embedded directly in `index.html`, so the HTML file can be copied and read on its own without the `figures/` folder or an internet connection. Use **View larger** above a figure to enlarge it, then scroll inside the figure if needed. The separate `figures/` files are retained as originals but are not required by the guide.

Keep the two PDFs beside the HTML file if you want the links to the original books and their pages to work. PDF page links depend on your browser’s PDF viewer. Search and copy buttons require JavaScript; the chapter index, figures, figure zoom, and reading content work without it.

To check the guide’s local links, figures, and chapter coverage with the Python standard library, run:

```sh
python -m unittest discover -s tests
```
